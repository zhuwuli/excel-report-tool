■ 工具信息
  名称    ：report_maker.py
  功能    ：自动化制作工程监测报表（期数递增 + 日期递增 + 天气更新 + PDF导出）
  工作目录：F:\myproject\rpt-maker\
  执行命令：echo 5,1,2,3,1,4 | python report_maker.py
           （格式：总期数,第1期间隔,第2期间隔,...）

■ 文件对应关系（历史沿革）
  test.py              → report_maker.single.py   （单期版，最原始版本）
  run_all.py           → report_maker.manual.py    （批量版，step5 需手动）
  run_all1.py          → report_maker.py           （当前在用，step5 全自动）
  run_all1_backup.py   → report_maker.backup.py    （备份）

■ 六步主流程
  Step 1  复制目录（期数+1，日期+自定义天数）
  Step 2  删除目录下所有 PDF 文件
  Step 3  修改 Excel 封面（期数、天气）
  Step 4  处理 Excel 日期列（全部用COM完成，触发RANDBETWEEN重算）
  Step 5  自动处理外部引用（pywinauto + COM混合方案）
  Step 6  Excel 转 PDF（COM 接口 ExportAsFixedFormat）

『 2026-04-28 』第二十天 - Step4 全部改用 COM，解决 I 列超范围问题
══════════════════════════════════════════════════════════════════════════════

  ■ 问题分析：
    - 代码生成的汇总表 I 列超出理论范围 ±0.21
    - 手工操作正常
    - I = (D-E)*1000，E = F数值 = RANDBETWEEN(-21,12)/100000 + D
    - 理论范围：-0.21 到 +0.12

  ■ 根本原因：
    - openpyxl 的赋值操作不会触发 Excel 重新计算 F 列
    - 手工操作复制 E→D 会触发 F 重新计算 RANDBETWEEN
    - openpyxl 写入的是 F 列的旧缓存值

  ■ 解决方案：
    - Step4 全部改用 COM 完成（模拟手工操作）
    - 封面修改和日期列处理一次完成
    - D=E 操作在 COM 里执行，触发 F 列重新计算
    - 读取 F 最新值写入 E

  ■ 代码修改：
    1. process_excel() 重写：不再用 openpyxl，全部 COM
    2. 新增 days 参数：更新第3列公式 =D1+days
    3. 封面修改改用 COM（否则被 COM 保存覆盖）

  版本：v3.8

『 2026-04-29 』第二十一天 - 打包 exe + PyQt5 图形界面
══════════════════════════════════════════════════════════════════════════════

  ■ 目标：
    - 双击 exe 弹出图形界面
    - 无需命令行
    - 点按钮操作

  ■ 核心问题：PyQt5 与 win32com 的 COM 冲突
    - PyQt5 需要 STA 模式
    - win32com 也需要 STA 模式
    - 同一进程里争抢 COM 线程模式
    - 直接导入会导致 COM 初始化失败

  ■ 解决方案：延迟导入机制
    - gui_app.py 删掉顶层 from report_maker import
    - _load_default_path() 函数内导入
    - start_process() 函数内导入
    - ProcessThread.run() 函数内导入

  ■ 代码修改：
    1. gui_app.py（7处）：
       - 删顶层导入
       - 延迟导入 report_maker
       - 恢复 QFileDialog / QMessageBox

    2. report_maker.py（5处）：
       - 新增 find_latest_folder()（GUI 自动检测最新一期）
       - 新增 run_pipeline()（GUI 专用入口）
       - find_all_excel_files() 过滤 ~$ 临时文件
       - pywinauto.Desktop 加 try/except 保护

    3. utils.py（1处）：
       - sys.stdout.isatty() 改为 sys.stdout is not None and sys.stdout.isatty()

  ■ 打包命令：
    ```bash
    pyinstaller --onefile --collect-all pywinauto \
      --hidden-import win32timezone --hidden-import win32crypt \
      --name "Excel报表工具_GUI版_v3.8" gui_app.py
    ```

  ■ 成果：
    - Excel报表工具_GUI版_v3.8.exe（64.4 MB）

    - 选文件夹、填参数、点按钮

『 2026-04-30 』第二十二天 - 尝试无后台启动 + Office/WPS 下拉框（部分回退）
══════════════════════════════════════════════════════════════════════════════

【目标功能】

  1. exe 无后台启动（不弹黑窗口）
  2. Office/WPS 下拉框动态切换
  3. 日志输出重定向到文本框

【尝试过程】

  ■ 1. 无后台启动：
     - 尝试：打包命令加 --noconsole 或 --windowed
     - 问题：日志输出完全丢失，界面无响应
     - 原因：ProcessThread 的 stdout 管道失效
     - 尝试方案：
       a. 重定向 sys.stdout 到 QTextEdit → 无效，子进程输出不走 sys.stdout
       b. 创建命名管道 → 复杂度高，不稳定
       c. 写临时文件，定时读取 → 延迟大
     - **结果：未能实现**，放弃此功能

  ■ 2. Office/WPS 下拉框：
     - 成功实现：gui_app.py 新增 QComboBox
     - 用户选择后设置 os.environ["RPT_EXCEL_TYPE"]
     - report_maker.py 的 run_pipeline() 读取环境变量
     - 实现动态切换

  ■ 3. 日志重定向：
     - 目标：日志输出到界面文本框而不是弹黑窗口
     - 问题：无后台启动后管道失效，日志无处输出
     - **结果：因无后台启动失败，日志重定向也未实现**

【最终决定】

  - **回退无后台启动功能**：保留黑窗口（控制台），确保日志可见
  - **保留 Office/WPS 下拉框**：这个功能成功实现且稳定
  - **放弃日志重定向**：控制台足够用

【代码变更】

  gui_app.py：
  - 新增 QComboBox（Office/WPS 下拉框）
  - 删掉顶层 from report_maker import（延迟导入，避免 COM 冲突）
  - start_process() 读取下拉框值传给 ProcessThread
  - ProcessThread 启动时设 os.environ["RPT_EXCEL_TYPE"]

  report_maker.py：
  - run_pipeline() 增加 excel_type 参数
  - excel_type=None 时从环境变量读取
  - 两处 EXCEL_VISIBLE 设置点加 DEBUG 打印

  打包命令（最终版本）：
  ```bash
  pyinstaller --onefile --collect-all pywinauto \
    --hidden-import win32timezone --hidden-import win32crypt \
    --name "Excel报表工具_GUI版_v3.10" gui_app.py
  ```
  （注意：去掉了 --console，因为默认就是控制台模式）

【教训总结】

  1. **有后台不是坏事**：
     - 黑窗口能实时看到日志
     - 出问题能看到具体报错
     - 调试方便

  2. **不要强求"完美"**：
     - 无后台启动确实美观
     - 但日志输出和调试信息更重要
     - 用户接受有黑窗口的版本

  3. **技术复杂度 vs 实用性**：
     - 命名管道、文件轮询等方案太复杂
     - 性价比低
     - 控制台输出是最简单可靠的方案

    - 程序误把临时锁文件当作正式汇总表交给 WPS 打开

  ■ 修复内容：
    - report_maker.py 中 find_excel_files() 增加 f.startswith('~$') 判断
    - 自动跳过所有 ~$ 开头的 WPS/Excel 临时锁文件
    - README.md 增加 Q6 故障说明
    - CHANGELOG.md 记录本次问题修复

『 2026-06-02 』v3.10 Hotfix - GUI 安全停止优化
══════════════════════════════════════════════════════════════════════════════

  ■ 问题发现：
    - GUI 中途点击“停止”后，可能残留 Excel/WPS 进程
    - 可能留下临时锁文件、半完成的 COM 状态或未关闭的工作簿

  ■ 根本原因：
    - 原停止逻辑使用 QThread.terminate() 硬终止后台线程
    - 线程可能正执行 report_maker.py 中的 Excel COM 操作
    - 硬终止时，wb.Close()、excel.Quit()、_kill_excel_process() 可能执行不到

  ■ 修复方案：
    - GUI 停止按钮改为协作式停止：
      1. stop_process() 调用 request_stop()
      2. 后台线程只设置取消标志，不再 terminate()
      3. run_pipeline() / process_single_batch() 在步骤边界检查 cancel_check()
      4. 用户请求停止时抛出 PipelineCancelled 并返回 status=cancelled

    - Excel COM 清理增强：
      1. process_excel() 增加 finally
      2. 取消或异常时尝试 Workbook.Close(SaveChanges=False)
      3. 尝试 Excel.Quit()
      4. 最后调用 _kill_excel_process() 清理残留 Excel 进程

  ■ 修改文件：
    - gui_app.py：停止按钮与关闭窗口逻辑改为 request_stop()
    - report_maker.py：新增 PipelineCancelled、check_cancelled()、cancel_check 参数传递
    - report_maker.py：process_excel() 增加 finally 清理逻辑

  ■ 验证结果：
    - python -m py_compile report_maker.py gui_app.py run_queue.py utils.py 通过
    - 模拟立即停止：run_pipeline() 返回 cancelled
    - 模拟 Excel 已打开后停止：确认调用 Close(SaveChanges=False)、Quit、_kill_excel_process()

  ■ 注意：
    - 新停止逻辑不是“立刻拔电源”，而是在下一个安全检查点停止
    - 如果正卡在 Excel COM 系统调用中，需要等待该调用返回后再收尾

『 2026-06-02 』v3.10 Hotfix - run_queue.py 路径自动化
══════════════════════════════════════════════════════════════════════════════

  ■ 问题发现：
    - run_queue.py 顶部写死了项目绝对路径
    - QUEUE_DIR、REPORT_MAKER、LOG_DIR 固定指向 F:\myproject\rpt-maker
    - PYTHON 固定指向 F:\anaconda\python.exe
    - 项目移动目录或换电脑后，需要手动修改源码才能运行

  ■ 修复方案：
    - 新增 PROJECT_DIR = Path(__file__).resolve().parent
    - QUEUE_DIR = PROJECT_DIR / "queue"
    - DONE_DIR = QUEUE_DIR / "done"
    - REPORT_MAKER = PROJECT_DIR / "report_maker.py"
    - LOG_DIR = PROJECT_DIR / ".logs"
    - PYTHON = sys.executable，使用当前运行 run_queue.py 的 Python 环境

  ■ 使用方式：
    - 用法不变，先进入项目目录：
      cd F:\myproject\rpt-maker
    - 预览：
      python run_queue.py --dry-run --yes
    - 正式处理：
      python run_queue.py -y -n -c

  ■ 验证结果：
    - python -m py_compile run_queue.py 通过
    - python run_queue.py --dry-run --yes 通过
    - dry-run 成功识别当前项目目录下的 queue\稼轩2 工程

  ■ 注意：
    - PYTHON = sys.executable 意味着调度器会使用当前 Python 环境
    - 运行前仍需确保当前 Python 已安装 openpyxl、pywin32、pywinauto、requests、PyQt5 等依赖
